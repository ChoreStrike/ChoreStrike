## Branch Guard for Agent Sessions (10-17)

- **Why**: on 2026-10-17 a second agent session committed into another session's worktree on `master` while that worktree held uncommitted work, and moved `master` past a qualified deployment candidate. Nothing broke, but nothing prevented it either: the branch rules were text only, and only Claude Code's `git push` needed a confirmation.
- **Guard**: tracked `.githooks/pre-commit` (executable), activated by `npm ci` / `npm install` through `prepare` → `scripts/git-guard.js install` (`core.hooksPath=.githooks`; skipped outside a git work tree such as the package builder, never replaces a different configured path). It refuses direct commits on `master`/`main` unless the user explicitly asked for that commit (`CS_ALLOW_MASTER=1` for one command) and commits on any branch other than the worktree's pin (`npm run branch:pin` / `branch:unpin` / `branch:status`, stored per worktree in the git directory); fast-forwards, merges and detached HEADs are unaffected. Tool-agnostic: Claude Code, Kilo and humans all commit through git.
- **Rules**: `master` always releasable, short-lived task branches, one session per worktree per branch with the branch recorded in `ACTIVE_TASKS.md`, a release freeze between qualification and deployment, never `--no-verify` — in the `git-workflow` skill, AGENTS.md (v7.1), `development.md` and `agent-spawning.md`.
- **Verification**: `gitGuard.spec.js` 9 cases drive real commits in throwaway repositories (master refusal and override, feature branch plus fast-forward, detached HEAD, pin mismatch/match/unpin, status, install idempotence, foreign hooks path, no-op outside git); a negative control against an empty hooks directory fails the two refusal cases.

- **TECH-TEST-004 — deterministic package-smoke freshness fixture**: the orchestration fixture now runs on a logical clock — the injected `now()` and every fixture report's explicit mtime come from it — so no assertion depends on filesystem or wall-clock timing. Freshness tests pin newer, equal, within-tolerance and beyond-tolerance report times; a new orchestration negative proves a predating report is still rejected, and the post-run drift test asserts the exact extraction-drift message (no alternate-error match, no sleeps or retries). Production freshness enforcement, including the CS-PLAN-085 two-second granularity tolerance, is unchanged. The original 2026-10-12 failure stays historical evidence.
- **TECH-DOCS-006 — clone-independent backlog link gate**: `check-backlog.js` resolves link targets against the paths git can see (tracked plus untracked-but-not-ignored, exact case) as well as the working tree, treating a directory as resolved when a visible file carries its prefix. A gitignored local directory or a case mismatch (invisible on Windows) can no longer pass locally and fail in CI. Untracked-not-ignored files count because new files ship in the same commit as their links (the same reason the monthly archive is read from the worktree). Self-test: new ignored-directory and case-mismatch cases, the link cases now use a resolving archive so the link is their only possible finding; a negative control without the index fails both new cases. The stricter check surfaced no further broken links.
- **TECH-DOCS-004 — Latin-1/C1 and cp1252 mojibake signatures**: the encoding gate now also flags a C1 control after a `U+00C2`/`U+00C3`/`U+00E2` lead (UTF-8 read as Latin-1), the same leads followed by any cp1252 80-9F character (the previous two signatures covered only `E2 80`/`E2 82`, so a cp1252 arrow `U+00E2 U+2020 U+2019` passed) and `U+00C2` followed by a Latin-1 symbol (`§` read as `U+00C2 U+00A7`). Self-test fixtures for all three plus a clean lead-character fixture. The whole-tree rescan found 49 real corruptions in nine tracked files (arrows, ellipsis, em dash, `≤` and section signs in `architecture.md`, `development.md`, `notifications.md`, `testing.md` and five integration-test comments), all repaired by reversing the mis-decoding; the tree is green.
- **TECH-PKG-001 — single owner-smoke case matrix**: `scripts/package-target.js` defines the language × width matrix and the derived counts (setup 1, verify 6) once; the owner smoke iterates it and both evidence validators (`run-package-smoke.js`, `export-package.js`) consume the counts, as do the Jest fixtures.
